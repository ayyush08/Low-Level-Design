# Introduction to LLD

## Definition

LLD is where your code starts to take shape. It is bridge between architecture and actual implementation. 

### Example


#### Real Life Example - Building a House

When you want to build a house, you first need to have a blueprint. The blueprint is like the high-level design (HLD) of your house. It shows the overall structure, the number of rooms, and how they are connected.

But before you can start building, you need to create a detailed plan for each part of the house. This is where low-level design (LLD) comes in. LLD is like the detailed plan that shows how each room will be constructed, what materials will be used, and how the electrical and plumbing systems will be installed.


#### Computer Science Example - Designing an Authentication System

When designing an authentication system, the high-level design (HLD) would outline the overall architecture of how to Login, Register, and Logout users. It would show the different components involved, such as the user interface, the backend server, and the database.

Then in the low-level design (LLD), you would go into detail about how each component will work. For example, you would specify the exact algorithms for password hashing, the database schema for storing user information, and the API endpoints for handling login and registration requests. LLD provides a clear roadmap for developers to implement the system effectively.

## Key Characteristics of LLD

1. Granular and code-level
2. Implementation-focused
3. Applies OOPS principles

## HLD vs LLD

| Aspect | High-Level Design (HLD) | Low-Level Design (LLD) |
| -------- | -------- | -------- |
| Purpose | System overview & modules | Detailed implementation & logic |
| Level of Detail | Abstract | Highly Detailed |
| Focus | Architecture, modules, interfaces | Class diagrams, methods, details |
| Outcome | Modules, System diagrams | Detailed class/method diagrams |


## Importance of Low Level Design (LLD)

1. **Avoids Rework**: Clearly defined logic and structure help catch design issues early, reducing costly changes during development.

2. **Improves Collaboration**: Acts as a shared reference for teams, ensuring everyone understands component behavior and integration points.

3. **Promotes Scalability**: Well-designed, modular components can handle growth and new features without major redesign.

4. **Encourages Best Practices**: Enforces use of clean code, design patterns, and OOP principles, leading to maintainable and robust systems.
